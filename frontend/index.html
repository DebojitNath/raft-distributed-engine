What is Raft and why is it important?

In distributed systems, ensuring that multiple machines agree on a shared state is one of the most fundamental challenges. Imagine a distributed database running on five different servers across the globe. If a client writes data to one server, how do we ensure the other four servers also record that data, even if network connections fail or servers crash? This is the problem of Distributed Consensus.

The Leader, the Followers, and the Candidates

Raft solves this by establishing a strong Leader. Under normal operations, all nodes are Followers, except for one node that is the Leader. Clients send commands only to the Leader, which appends the commands to its log and broadcasts them to the Followers.

If a Follower stops hearing from the Leader (via heartbeats), its "election timer" runs out, and it becomes a Candidate. It requests votes from the other nodes. If it gets a majority of votes, it becomes the new Leader!

Why Raft?

Before Raft, the Paxos algorithm was the standard for consensus. However, Paxos is notoriously difficult to understand and implement correctly. Raft was designed specifically to be understandable. It separates the consensus problem into three independent subproblems:

  • Leader Election: A new leader must be chosen when an existing leader fails.
  • Log Replication: The leader must accept log entries from clients and replicate them across the cluster.
  • Safety: If any server has applied a particular log entry to its state machine, no other server may apply a different command for the same log index.
